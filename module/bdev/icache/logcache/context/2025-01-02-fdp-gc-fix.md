# FDP Mode GC/Evict Fix - 2025-01-02

## Summary
FDP 모드에서 GC/Evict 관련 여러 문제 수정

## Issues Fixed

### 1. GC Write Hang (ZRWA Constraint)
**문제:** GC 16KB write가 hang됨 - `gc_write_done` callback이 호출 안됨

**원인:** FDP 모드에서도 ZNS의 ZRWA constraint가 적용됨
- `can_submit()`에서 `offset + len <= flushed_wp + 1MB` 체크
- 새 zone의 `flushed_wp = zone_start_offset`
- GC의 `dst_offset`이 zone 중간에 있으면 체크 실패

**수정:**
- `ZoneQueue`에 `is_fdp` 플래그 추가 (`log_cache_wrapper.cpp:247`)
- `can_submit()`에서 FDP 모드면 ZRWA constraint skip (`log_cache_wrapper.cpp:273-276`)
- `open_zone_zrwa_async()`에서 FDP 모드일 때 `is_fdp = true` 설정 (`log_cache_wrapper.cpp:1386`)
- `clear_zone_state()`에서 `is_fdp` 리셋 (`log_cache_wrapper.cpp:1461`)

```cpp
// ZoneQueue::can_submit()
if (is_fdp) {
    return true;  // FDP mode: no ZRWA constraints
}
```

### 2. Evictor Empty 에러
**문제:** `start_gc_or_evict: both prepare_gc and prepare_evict failed!` 에러

**원인:** 정상 상황인데 에러로 처리됨
- `need_gc_or_evict()`: `free_pool <= 10`이면 GC 트리거
- 모든 full segment가 evict되고 새 segment들이 아직 full 안됨
- Evictor가 비어있어서 `choose_segment()` 실패

**수정:**
- `EvictPolicy` 베이스 클래스에 `empty()` 가상 메서드 추가 (`evict_policy.h:43-44`)
- `GreedyEvictPolicy`에서 `empty()` 구현 (`evict_policy_greedy.h:31`)
- `need_gc_or_evict()`에서 evictor가 비어있으면 false 반환 (`log_cache.cpp:962-964`)
- 에러 로그 제거 (`log_cache_wrapper.cpp:3282-3283`)

```cpp
// log_cache.cpp::need_gc_or_evict()
if (evictor->empty()) {
    return false;  // Nothing to evict
}
```

## Architecture Notes

### Segment Lifecycle
```
free_pool -> active_seg (writing) -> evictor (full) -> evict -> free_pool
```

### FDP vs ZNS
- **ZNS:** Zone write pointer, ZRWA flush 필요
- **FDP:** Random write 가능, zone 개념 없음 (virtual zone for eviction only)

### Key Constants
- `ASYNC_GC_TRIGGER_SEGMENTS = 10`: free_pool <= 10이면 GC 트리거
- `STRIPE_WIDTH = 2`: 2개 zone에 striping
- Segment size = 4GB (2 zones * 2GB each)
- Zone size = 2GB (0x80000 blocks * 4KB)

## Testing
Random 4KB write workload with FDP SSD as cache, regular SSD as backend.
- Evict 정상 동작 (1.3-1.6 GB/s read, 10-40 GB/s write to backend)
- GC copy 정상 동작 (blocks_to_copy > 0 일 때)
- Evictor empty 상태에서 hang 없이 정상 진행
